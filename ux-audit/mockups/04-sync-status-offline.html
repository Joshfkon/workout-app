04 · Did my set save? — visible write status + offline queue

Sets are written to Supabase one-by-one, but there is zero save/sync feedback — and the service worker is network-only for API calls, so in a basement gym the write silently fails with a toast error at best. Hevy and Strong both queue offline writes. Proposed: per-set status glyphs (saving → saved → queued), an offline banner, and an IndexedDB outbox the SW flushes on reconnect. Undo lives in the same toast pattern nutrition already uses.
